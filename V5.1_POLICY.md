# WMBO Rule Policy V5.1 RC3

RC3 is a focused anti-lock-in correction of RC2 after the 36-run targeted comparison.
It deliberately preserves RC2 geometry reliability, phase routing weights, sparse exploration,
progress-centred reward/trust/cooldown, new-best local follow-up, phase-decayed information,
late optimize-only candidate selection, and success-extended local macros.

## RC3 changes

1. **Rolling local-operator dominance suppression**
   - Inspect the last 12 objective evaluations.
   - If one local operator (GP-EI, TuRBO, or CMA) accounts for at least 70% of that window
     and its last four completed macros all failed to improve the incumbent, its routing score
     receives a soft `0.65` multiplier.
   - The operator remains legal; this is not a hard mask.
   - Any recent successful macro clears the dominance penalty.

2. **Evidence-gated underperforming-operator penalty**
   - Activate only after an operator has at least five completed macros.
   - Require the last four macros to contain no incumbent improvement.
   - Compare Bayesian-smoothed macro success rates across the three local operators.
   - If an operator's success rate is below 25% of the best local success rate, apply the same
     soft `0.65` routing multiplier.
   - This targets cases such as repeated GP-EI selection after the run has already established
     that CMA is far more productive.

3. **Conservative combination rule**
   - If both anti-lock-in conditions fire for the same operator, the penalty remains `0.65`;
     the multipliers do not stack to `0.4225`.
   - Exploration operators are unaffected; their existing sparse gates/cooldowns remain unchanged.

4. **Traceability**
   - `rule_policy_version` and `policy_revision` are `5.1-rc3` / `v5.1-rc3`.
   - Logs expose pre-penalty scores, effective score multipliers, penalty reasons, and rolling
     local-operator shares so RC3 behaviour can be audited directly from `observations.csv`.

## Validation sequence

Run the same 36-run targeted suite first:

```bash
python run_benchmark.py --config configs/synthetic_bbob_portfolio_v51_rc3_targeted.yaml
```

Primary checks:
- f22 d5: reduce seed-to-seed lock-in variance without losing f22 d10 recovery.
- f12: retain RC2's recovery and avoid renewed GP-EI over-allocation.
- f16: do not worsen final regret or the partially recovered anytime AUC.
- Exploration share should remain close to RC2; RC3 does not change exploration gates.

Only then run the full 96-run suite:

```bash
python run_benchmark.py --config configs/synthetic_bbob_portfolio_v51_rc3_formal.yaml
```
